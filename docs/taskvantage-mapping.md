# TaskVantage de-identification mapping

The Active Directory content shipped by `modules/active-directory` is derived from an
earlier Starbucks-flavored POC environment. Every identifiable construct was renamed to
the fictional company **TaskVantage** (a workforce/task-management SaaS whose field teams
operate at client **Sites** grouped into **Territories**). This document is the canonical
mapping; `tools/gen-taskvantage-ous.mjs` encodes the OU-tree portion and enforces a
deny-list so nothing identifiable can reach the generated data.

## Core identity

| Construct | Value |
|---|---|
| AD DNS domain | `taskvantage.local` |
| NetBIOS domain | `TASKVANTAGE` |
| DC computer name | `TV-<spoke>` (unique per spoke, 15-char NetBIOS limit) |
| Top-level OU | `OU=TASKVANTAGE` |
| Schema attribute prefix | `tv` (LDAP names), `tv-` (CN) — replaces `sbux`/`sbux-` |
| Auxiliary classes | `tvUser`, `tvGroup` ("TaskVantage User/Group Extension") |
| Schema OID base | `1.2.840.113556.1.8000.2554.31284.19867.42055.27913.58120.4816325.9203716` (freshly generated Microsoft-scheme random OID; sub-arcs `.1.2.1.N` classes / `.1.2.2.N` attributes preserved) |

## Schema attributes

Mechanical `sbux` → `tv` rename for all 37 attributes, plus semantic renames where the
original name itself was identifying:

| Original | TaskVantage |
|---|---|
| `sbuxPartnerNumberAsInteger` | `tvAssociateNumberAsInteger` |
| `sbuxOrgStoreID` | `tvOrgSiteID` |
| `sbuxOrgDistrictID` | `tvOrgTerritoryID` |
| `sbuxStoresManaged` | `tvSitesManaged` |
| `sbuxOnTLA` | `tvOnFieldNet` ("TLA" was company jargon) |

Descriptions updated to match (Partner → Associate, Store → Site, District → Territory).
Syntax, OMSyntax, single/multi-valued, and OID sub-arc positions are unchanged.

## Enterprise OU tree (242 OUs)

Regenerated by `tools/gen-taskvantage-ous.mjs` from the source repo's inline OU array
(never from customer-derived CSV/LDIF data). Token substitutions, longest-first:

| Original token | Replacement |
|---|---|
| `STARBUCKS` | `TASKVANTAGE` |
| `SBUX Wireless Guest Accounts` | `TV Wireless Guest Accounts` |
| `China …` (region) | `APAC …` |
| `Retail Stores` / `Distribution Lists Retail` / `Retail Contact Objects` | `Field Sites` / `Distribution Lists Field` / `Field Contact Objects` |
| `Distribution Lists Partner Blend` | `Distribution Lists Associate Blend` |
| `Stores` / `Stores-LS` / `StoreLaptops` | `Sites` / `Sites-Managed` / `SiteLaptops` |
| `Licensee` / `Licensed Store DL` | `Resellers` / `Reseller Site DL` |
| `MICROS` / `3C` (vendors) | `FieldServe` / `TriCore` |
| `Kronos` | `ShiftTrack` |
| `CyberArk NonProd` | `PAM NonProd` |
| `SCCO/DHL Danzas Users` | `NorthHaul Logistics Users` |
| `HPR Link Logistics` | `LinkPoint Logistics` |

Numeric Cloud OUs (`00090`, `00345`, …), `EXT`, `EMEA`, `PAT *`, `FIM Managed Groups`
(Microsoft product name) and generic server/group/account OUs are kept as-is — they are
not identifying.

## Deny-list gate

`gen-taskvantage-ous.mjs` fails if the generated output matches:
`STARBUCKS|SBUX|Starbucks|sbux|Barista|Pike Place|DHL|Danzas|MICROS|Kronos|CyberArk|VISFed|Licensee|Licensed Store|GlobalPSP|China`

Run the same regex over `modules/active-directory/files/ad-setup.ps1` after any edit to
the directory-content sections.
